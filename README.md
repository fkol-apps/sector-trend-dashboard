# セクター別トレンド銘柄ダッシュボード

**https://fkol-apps.github.io/sector-trend-dashboard/**

日本株（TOPIX500相当）と米国株（S&P500）を、GICS 11セクター × 3つの時間軸（長期／中期／短期）の
タイルで俯瞰するためのツールです。

> **本ツールは過去の値動きに基づく機械的なスクリーニング結果であり、投資助言ではありません。投資判断はご自身の責任で行ってください。**

個人の投資判断における「一次スクリーニング」用であり、売買を推奨するものではありません。

## 構成

```
.
├── config.yaml                 # 重み・しきい値・フィルタ条件（調整はここだけ）
├── data/
│   ├── sector_map.json         # GICS 11セクター定義／東証33業種→GICS／銘柄別の上書き
│   ├── universe_jp.csv         # 日本株ユニバース（ticker,name,sector）
│   └── universe_us.csv         # 米国株ユニバース（ticker,name,sector）
├── scripts/
│   ├── fetch_universe.py       # ユニバースCSVの生成（JPX / Wikipedia）
│   └── build_data.py           # 株価取得＋スコア算出＋JSON出力（Step2以降）
├── docs/                       # GitHub Pages で配信する静的サイト
│   ├── index.html
│   └── data/{jp,us}.json       # フロントが読む唯一のデータ
├── tests/                      # スコア算出ロジックの単体テスト
└── .github/workflows/          # 平日 JST 7:00 の定期実行
```

アーキテクチャはサーバーレスです。Python スクリプトが JSON を生成してリポジトリにコミットし、
フロントエンドは自分の JSON だけを読みます。**フロントから外部APIは一切叩きません。**

## ユニバースの編集

`data/universe_jp.csv` / `data/universe_us.csv` は `ticker,name,sector` の3列です。
そのまま手で編集して銘柄を足し引きできます（`sector` は GICS 11セクターの英語キー）。

自動生成し直す場合:

```bash
.venv/Scripts/python.exe scripts/fetch_universe.py --market both
```

- 日本株: JPX「東証上場銘柄一覧」(`data_j.xlsx`) から **内国株式 かつ 規模区分が TOPIX Core30 / Large70 / Mid400**
  ＝ TOPIX500相当を抽出し、33業種区分を `data/sector_map.json` で GICS 11セクターに寄せます。
- 米国株: Wikipedia の S&P 500 構成銘柄表から Symbol / Security / GICS Sector を取得します。
  `BRK.B` のようなティッカーは yfinance 形式の `BRK-B` に変換します。

再実行するとCSVは**上書き**されます。手編集を残したい場合はコミットしてから実行してください。

### セクター分類の直し方

`data/sector_map.json` の2箇所で調整します。

- `tse33_to_gics`: 東証33業種 → GICS 11セクターの既定マッピング。
- `ticker_overrides`: 業種区分と実態がずれる銘柄を個別に上書き（例: `"9432.T": "Communication Services"`）。
  既定マッピングより優先されます。日本株は `7203.T` 形式、米国株は `AAPL` 形式で書きます。

## 重みの調整

`config.yaml` の `weights` を編集します。長期／中期／短期それぞれについて、各指標の重みを指定します。
合計が1でなくても内部で正規化されます。フィルタ条件（売買代金・株価・上場期間）や
RSIのしきい値、抽出銘柄数（`scoring.top_n`）も同じファイルにあります。

## データ生成

```bash
.venv/Scripts/python.exe scripts/build_data.py --market jp     # docs/data/jp.json
.venv/Scripts/python.exe scripts/build_data.py --market us     # docs/data/us.json
.venv/Scripts/python.exe scripts/build_data.py --market both   # 両方
```

動作確認用のオプション:

```bash
# 10銘柄だけで指標とスコアを表で確認（JSONは書かない）
.venv/Scripts/python.exe scripts/build_data.py --market jp --dry-run --tickers 7203.T,6758.T,8306.T
.venv/Scripts/python.exe scripts/build_data.py --market us --dry-run --limit 20
```

一部銘柄の取得に失敗しても処理は完走します。失敗した銘柄はログに出力され、
JSON の `failed` 配列にも残ります。

### スコアの算出手順

1. 各銘柄について指標を算出（`scripts/trend_core.py`）
2. 事前フィルタ（上場期間・売買代金・株価）で対象を絞る
3. 残った銘柄**全体**で各指標を z-score 化し、`zscore_clip` で外れ値をクリップ
4. `config.yaml` の重み（正規化済み）で加重合計 → 合成スコア
5. セクター × 時間軸ごとに上位 `top_n` 銘柄を抽出

スコアは**そのユニバース内での相対値**です。市場が違えば基準も違うので、
日本株のスコアと米国株のスコアを直接比べることはできません。


> ブラウザのセキュリティ制限（file:// では JSON を fetch できない）によるもので、
> その場合は上のコマンドを案内する画面が出ます。GitHub Pages 上では通常どおり動きます。
> Claude Code から確認する場合は `.claude/launch.json` の `sector-trend` を使ってください。

### 2つの表示モード

ヘッダーの **マップ / リスト** で切り替えます（既定はマップ）。

#### マップ（既定）

**1セクター = 1枚の正方形カード**。カードの中身は「時間軸（列）× 順位（行）」の 3×3 ヒートマップで、
セルに置くのは 銘柄名・ティッカー・その時間軸のリターン の3つだけです。

- **セルの色 = スコア**（市場全体での相対強度）。強い＝青、弱い＝オレンジ、
  濃さは `|スコア| = 1.5` で最大になります。掲載銘柄のスコアは概ね 0〜2.5 に分布するので、
  この値にすると中位の銘柄にもはっきり色がつきます（`TINT_SCALE` で調整可）。
- **カードはセクターの強い順**に並びます。並べ替えの基準は
  「表示中の時間軸における掲載銘柄の平均スコア」で、その値をカード右上のピルに出しています。
  時間軸を絞り込むと、その時間軸での強さ順に並び替わります。
- 1600×900 で **全11セクターが1画面**（6枚×2行）に収まります。1265px幅で4枚×3行。
- セルにカーソルを合わせるとスコアと市場全体順位がツールチップで出ます。
  クリックすると詳細モーダル（1年チャート＋スコア内訳）。
- 上位3銘柄に満たない枠は、埋めずに破線の空セルにします。

> 色を「騰落」ではなくスコアにしているのは、掲載されるのが各セクターの上位3銘柄だからです。
> 実データでは99タイルのリターンはほぼ全部プラス（マイナスは0〜数件）で、
> 騰落の符号で塗ると全部同じ色になり情報になりません。スコアで塗ると
> 「弱いセクターの1位は市場全体では平凡」という差がそのまま濃淡に出ます。

#### リスト

一覧性を最優先にした高密度グリッドです。セクターの並び順はマップと同じ強い順で、
左のレールに強さ（平均スコア）を出しています。**1行 = 1セクター**、列が **長期 / 中期 / 短期**。
時間軸の見出しはヘッダーに1度だけ置き、セクター名は左のレールにまとめています。

- タイルに載せるのは ティッカー / 銘柄名 / 現在値 / 前日比 / 該当時間軸のリターン / スコア。
  **チャートは盤面には出さず、タイルをクリックしたモーダルでのみ表示**します。
- タイルの背景と左のバーは合成スコアの強さを表します。色は**青＝強い / オレンジ＝弱い**の
  一系統で、緑〜赤は使っていません（色覚多様性への配慮）。色は補助であり、
  スコアとリターンの数値は必ずタイル上に併記しています。
- 画面幅 1440px 以上ではタイルが1行に畳まれ、さらに縦が詰まります
  （1600×900 で全11セクターが約1.4画面、8セクターが一度に見える密度）。
- 900px 以下では1セクター1カラムに折り返し、各列に時間軸のラベルが付きます。
- 上位3銘柄に満たないセクターは埋めずに、実際の件数を表示します。
- ダークモードは OS / ブラウザの設定に追従します。

### 操作

| 操作 | 動き |
| --- | --- |
| ヘッダーの **日本株 / 米国株** | JSON を差し替えるだけで、ページ遷移しません |
| ヘッダーの **マップ / リスト** | 表示モードの切り替え |
| **長期 / 中期 / 短期** のチップ | 表示する時間軸を絞り込みます（列数が変わる）。最低1つは残ります |
| **すべて** のチップ | 3つの時間軸をすべて表示に戻します |
| タイルをクリック | 詳細モーダル（1年チャート＋スコア内訳＋Yahoo Financeリンク） |
| Esc / 背景クリック / × | モーダルを閉じる |

表示状態は URL のクエリに入るので、そのまま共有できます。

- `?market=us&view=map` — 米国株をマップ表示
- `?view=list` — リスト表示
- `?market=jp&tf=long` — 日本株の長期だけを表示
- `?market=us&tf=mid,short` — 米国株の中期と短期

### 詳細モーダル

- **1年チャート**: 盤面には出さず、ここでのみ表示します。終値に 20 / 50 / 200日SMA を重ねます。線は色に加えて
  **線種（実線・破線・点線）でも区別**できるようにしてあります。凡例には各線の最新値を表示。
- **スコア内訳**: 3つの時間軸それぞれについて、指標ごとの「実測値 / z / 重み / 寄与」を表にします。
  寄与＝ z × 重み で、その合計が合成スコアです。どの指標がスコアを押し上げ（下げ）ているかが分かります。
- **Yahoo Finance** の該当ページへの外部リンク（日本株は finance.yahoo.co.jp、米国株は finance.yahoo.com）。

## 自動更新（GitHub Actions）

`.github/workflows/update-data.yml` が **平日の日本時間 朝7:00** に動きます
（cron は UTC 表記で `0 22 * * 0-4`）。手動実行（Run workflow）もでき、市場を選べます。

やっていること:

1. 依存関係をインストール
2. `pytest` でスコア算出ロジックのテスト
3. `python scripts/build_data.py --market both` で株価取得〜JSON生成
4. 変更があればコミットして push（Pages が自動で再デプロイされる）

この時刻にしている理由は、日本株はその時点で前営業日の終値が確定しており、
米国株も当日 6:00 JST に引けた終値が取得できるためです。

### コミットの畳み方（リポジトリを太らせない工夫）

表示用の `docs/data/{jp,us}.json` は合計約2MBあり、中身が毎日ほぼ全部入れ替わります。
そのまま毎日コミットすると **1年で約110MB** リポジトリが膨らみます。

そこで、データ更新のコミットは **直前のデータコミットに畳みます**（`git commit --amend` して
`--force-with-lease` で push）。直前がコードのコミットのときは畳まず新しいコミットを作るので、
コードの履歴が書き換わることはありません（コミットメッセージの `chore(data):` で判定）。

これにより、フルJSONの古い版はGitの到達不能オブジェクトになり、リポジトリは
**常に最新の1日分**だけを保持します。

畳むのは次の3つをすべて満たすときだけで、ひとつでも欠けたら通常のコミットにフォールバックします。

1. **完全なクローンである**こと
2. HEAD に親コミットがあること
3. 直前のコミットがデータ更新のコミットであること

1が要るのは、`actions/checkout` の既定 `fetch-depth: 1`（浅いクローン）では HEAD に親が無く、
`git commit --amend` が**親を持たないルートコミット**を作ってしまうためです。
その状態で force push するとリモートの履歴が丸ごと置き換わります
（実際に一度発生させました。`fetch-depth: 0` の明示と上記のガードで対策済み）。

### 履歴スナップショット（永久保存）

畳むと過去のデータが残らないので、**その日の選定結果だけ**を別途 `data/history/YYYY-MM-DD.json`
に1日1ファイルで積み上げます。チャート系列を含まないので **1日あたり約28KB**、
年間でも数MBです（フルJSONを残す場合の約1/70）。

```jsonc
{
  "date": "2026-09-04",
  "markets": {
    "jp": {
      "price_date": "2026-09-04", "generated_at": "...", "scored": 490, "failed": 0,
      "picks": [
        { "sector": "Energy", "tf": "long", "pos": 1, "ticker": "5020.T",
          "name": "ENEOSホールディングス", "price": 1358.5,
          "score": 0.303, "rank": 115, "ret": 0.5985 }
      ]
    },
    "us": { }
  }
}
```

ティッカーと日付が残っていれば株価は後から取り直せるので、
「この日に選ばれた銘柄がその後どうなったか」の検証はこれだけで足ります。
不要なら `config.yaml` の `history.enabled` を `false` にしてください。

## 仕様上の判断メモ

作業中に仕様が明示されていなかった箇所について、以下のデフォルトを選びました。

| 項目 | 判断 | 理由 |
| --- | --- | --- |
| 日本株ユニバースの母集団 | JPXの規模区分で TOPIX500 を抽出 | 日経225やJPX日経400は機械可読な一次配布がなく、TOPIX500はJPX配布ファイルの `規模区分` 列だけで確定できる |
| 市場区分の絞り込み | プライムではなく「内国株式」で絞る | 市場再編後、TOPIX500構成銘柄の一部がスタンダードに在籍しているため（現時点で3銘柄） |
| ユニバースCSVの列 | `ticker,name,sector` の3列に固定 | 仕様どおり。元の33業種区分は保持していないので、分類を直すときは `sector_map.json` 側を見る |
| `sector` 列の値 | GICS英語キー（`Information Technology` 等） | 日米で軸を揃えるため。画面表示用の日本語名は `sector_map.json` の `ja` を使う |
| 日本株の銘柄名 | NFKC正規化して全角英数字を半角に | JPX原本が `ＩＮＰＥＸ` のような全角表記のため |
| JPXファイルのURL | 一覧ページからリンクを解決し、失敗時のみ既知URLにフォールバック | JPX側でファイル名・拡張子が変わる（実際に `.xls` → `.xlsx` に変更済み） |
| S&P500 の重複ティッカー | GOOG / FOX / NWS（2本目の株式クラス）を除外し500社にする | 同一企業がセクター上位の2枠を占めてしまうため。残すのは GOOGL / FOXA / NWSA |
| 欠損指標の扱い | z=0（ユニバース平均）として合成し、銘柄自体は落とさない | 1指標が欠けただけで銘柄が消えると、セクターによっては候補が枯れるため |
| z-scoreクリップで同点になる場合 | 表示スコアは同点のまま、並べ替えだけクリップなしスコアで行う | 強い銘柄ほど上限に張り付いて同点が発生する。表示値を偽らずに順序だけ確定させる |
| 出力JSONに載せる銘柄 | どこかのセクター×時間軸で上位に入った銘柄のみ | 全銘柄のチャートを載せるとファイルが数十MBになる。1市場あたり約1MB（gzip 230〜270KB）に収まる |
| データ更新の履歴 | フルJSONはコミットを畳み、選定結果だけ日次で永久保存 | フルJSONを毎日残すと年110MB。チャート系列は後から再取得できるので、残す価値があるのは「その日何が選ばれたか」だけ |
| 定期実行の時刻 | 平日 JST 7:00（UTC 22:00 日〜木） | 日本株の前営業日終値と、当日6:00 JSTに引けた米国株終値の両方が確定している時刻 |
